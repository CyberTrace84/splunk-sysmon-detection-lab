## 1. Summary
The detection fired on `powershell.exe` launched with an encoded command,
a hidden window and an execution-policy bypass. These are flags commonly
used by attackers to hide what a script does.

## 2. Evidence
- **Alert reasons:** Encoded command, Hidden window, Execution policy bypass
- **Parent process:** C:\Windows\System32\WindowsPowerShell\v1.0\powershell.exe
- **Command line 1:** `powershell.exe -NoProfile -WindowStyle Hidden -EncodedCommand dwBoAG8AYQBtAGkA...`
- **Command line 2:** `powershell.exe -NoProfile -ExecutionPolicy Bypass -Command "Write-Output 'test'"`
- **Screenshots:** `screenshots/07` to `screenshots/11`

## 3. Analysis
1. **Parent process:** Windows Terminal launched PowerShell, which is normal for an interactive session.
2. **Payload:** the base64 decodes to `whoami`, which only prints the current
   username. No download, no network connection and no file written.
3. **Context:** the user is a local interactive account, and the activity
   happened at the time I ran my test.
4. **Related activity:** I searched Sysmon for other events from this host around the same time and found nothing unusual.

## 4. Verdict
**True positive for the technique, not a real incident.** The detection works
as designed. In a production environment, with this parent process and
payload, I would classify it as low risk after verifying the user.

## 5. Escalation decision
**Not escalated** in this case. I would escalate to L2 if:
- the parent process was Word, Excel, a browser or a PDF reader;
- the decoded payload downloaded or ran remote content;
- the account was not expected to use PowerShell;
- the same host showed other suspicious activity (new users, scheduled
  tasks, outbound connections).

## 6. Recommended actions (if this were real)
- Confirm with the user that they ran the command.
- Collect the full command line and decode every encoded payload.
- If malicious: isolate the host, reset the account's credentials, and
  search other hosts for the same command line.

## 7. Detection notes
- False positives expected: deployment scripts and installers that use
  `-ExecutionPolicy Bypass`.
- Tuning: 10-minute lookback and 30-minute suppression per host.
